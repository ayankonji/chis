### 技术决策
- 前端使用 localStorage 作为 fallback，GitHub Pages 纯静态部署无压力
- base 路径设为 /chis/ 匹配英文仓库名
- 图片使用 Unsplash 在线链接，无需本地图片资源

### 踩坑记录
- **BrowserRouter basename 不匹配 vite base**：main.jsx 的 basename 是 `/今天吃什么`，vite.config.js 的 base 是 `/chis/`，导致路由不匹配白屏。修复：统一 basename 为 `/chis`。
- **GitHub Pages SPA 404 问题**：BrowserRouter 在 GitHub Pages 上直接访问子路由会 404，因为静态托管不支持服务端路由重写。修复：改用 HashRouter，URL 变为 `/#/draw` 形式，GitHub Pages 只处理 `/chis/` 路径，hash 部分由前端处理。

### 云端后端迁移（Supabase + Vercel）
- **新增 Vercel Serverless Functions**：`api/` 目录下创建了 foods、draw、categories、health 等 API 路由
- **Supabase 连接**：使用 `@supabase/supabase-js` 连接 PostgreSQL 云数据库
- **前端适配**：`api.js` 中 `API_BASE` 可配置，支持本地开发和远程后端切换
- **部署架构**：GitHub Pages（前端静态）→ Vercel Functions（后端 API）→ Supabase（数据库）
- **CORS 处理**：后端 API 设置了 `Access-Control-Allow-Origin`，允许 GitHub Pages 域名访问
- **Vercel CLI 部署成功**：`npx vercel deploy --token xxx`，后端域名 `https://chis-api.vercel.app`
- **环境变量踩坑**：`vercel env add` 通过管道设置时，值会包含换行符导致 `FUNCTION_INVOCATION_FAILED`。修复：使用 `echo -n` 避免换行符
- **Vercel 项目链接踩坑**：首次部署后再次部署提示 "Detected linked project does not have id"。修复：删除 `.vercel/` 目录后重新部署
